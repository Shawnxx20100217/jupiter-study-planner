# Jupiter Ed 读取约定

独立运行器是默认同步入口。默认只读取当前学生可见的数据，不提交作业、不改分数、不发送消息；若实例显式开启 `jupiter_done_writeback_enabled`，只把个人 To Do 的 Done 标记写回同一条作业，不触碰提交或评分。实际成功或失败以私密 `run-status.json` 和报告覆盖为准。

## 独立采集范围

`scripts/jupiter_collector.py` 使用 Scrapling 0.4.15 的专用 Chrome profile，读取常规网页界面，不调用模型或官方 Jupiter API。Python 3.12 环境、私密实例配置和登录命令见 [README](../README.md)。

Jupiter 自带 Calendar 是截止日期的事实来源。runtime 不把它复制成第二套任务系统，而是在本地状态上生成 `*-calendar.md` 月视图和 RFC 5545 `.ics`。`.ics` 中的精确时间使用 UTC 表示；只提供日期的作业可按实例配置导出为全天事件，并明确标注时间待确认；未知或有歧义的日期只留在月视图和待核实列表。

1. 对照实例中的学生、学校学年、当前学期和课程列表校验页面。身份、学年或课程不一致就停止，不把另一份数据覆盖到旧账户。URL 仍含 `/login/` 不代表必然掉线，实际身份与页面结构才是依据。
2. 逐科打开当前学期课程列表，切换后核对课程标题与教师。读取列表内作业；不以 To Do、本周或本月作为全学期范围。解析器检查 Due/Assignment/Score 表头、固定数据列、稳定 ID 和重复行冲突；空页、字段不足或结构变化报错，不能静默视为没有任务。
3. 读取 Calendar 中与未评分记录相关的月份，将匹配课程/题目的明确日期写为 `confirmed_due_date`。没有唯一匹配的日期保持待核实；不假设学年八月开学，不随意补年份。
4. 收集 **Last 14 days** 范围内、与课程教师匹配的通知预览。没有逐条打开全文或自动语义理解；新增或内容变化进入待核对列表，不由预览自动生成作业、解释课堂限制或推断截止日期。
5. 结束前再次校验身份与课程。成功后 runtime 合并状态、保留个人进度、生成队列和本地变化记录；失败保留最后成功的数据。

`coverage.complete` 仅表示本次已配置的可见课程、相应 Calendar 读取与限定通知预览范围已走完。报告显示课程和范围说明，不能称为“全部通知全文”或“所有任务细节均已理解”。课程、学期、通知筛选或页面结构变化时，不得悄悄改为模型浏览器采集。

当前收集不是官方稳定接口。来源作业行的 `click="goassign(数字)"` 只作为可读来源 ID 字符串解析，不能执行该属性、调用内部函数或私有网络接口。数值成绩只转为 `graded`，不写入报告。

## 稳定身份、日期与提交证据

- 先用 `source_assignment_id` 与课程匹配已有任务；没有来源 ID 时才做唯一课程/标题匹配。有多个候选则进入 review，不能静默合并或重复计时。personal 估计、剩余时间和本地完成状态独立于 source。
- 保留截止原文和采集时间。明确 Calendar 日期须与列表月日相容。既有明确截止时刻在新日期相同时继续保留；日期改变或冲突时清除过时 `due_at`，保留旧证据供核实。
- 空日期保持 unknown；学年两年范围内的 MM/DD 不能唯一定位时进入待核实。只有明确年份、相容既有映射或唯一 Calendar 日期才确定日期。学校时区来自实例配置，不根据电脑位置猜测。
- 仅日期时不补造 23:59。规划器可使用前一天完成的保守目标，但必须与教师截止分开。“Start of class”“next class”须核对真实日期与课时，不能由空课表推断。
- Done 是个人整理，不是已提交或教师已收取。空白、破折号、`/ 满分`、未评分不是未交；`graded` 是评分证据，不直接映射完成。只有明确的 submitted/completed/missing 才按对应证据更新；显式启用写回时，个人 Done 只映射本地完成状态，不改变提交证据。
- 新出现的已评分历史不批量导入；已有记录后来显示 graded，可保留为 reference 并说明提交证据待核实。新发现历史未评分没有明确缺交证据时先待核实；已有 active 不仅因为日期已过就排除。
- 未找到任务不表示完成或删除。partial 扫描不能删除旧任务；完整列表中消失也保留最后观察时间。既有 derived 准备项和 superseded 汇总关系保留来源链，注明本次属于保留而非重新读取的原始行。

## 规划分类与通知解读

分类与提交状态分开存，详见 [数据格式](data-format.md)。

- `active`：适合在用户确认的学习窗口推进。
- `in_class`：已确认必须在课堂/活动现场做的动作，例如展示时互评且不得提前填写。只作课堂提醒，不从标题自行新增此规则。
- `reference`：信息、明确免做、Participation 评分项，或需要核实的历史记录。用 `planning_note` 保留原因；免做不能伪装为已提交。
- `superseded`：汇总布置已由真实细分任务完整覆盖，保留关联 ID 不重复计时。部分未覆盖的要求仍独立保留。

import 自动 reference 遇明确 missing 可恢复 active，但不能覆盖人工课堂/参考决策。教师通知以稳定 ID、作者、标题和正文比较；Today 变 Yesterday 不算新内容。预览与来源进入 `pending-review.json`，无新增时仍保留未处理条目。用户要求解读时再核对全文与现有作业，确认独立动作、课堂限制和截止证据后更新任务。

Bell Schedules 可在有可靠课时证据时作为 busy 参考；没有课的间隔不自动成为可学习窗口。多科挤在同一 Period 等异常须标注未核实，不猜课序、自习或下次课。只有用户明确的可用时间进入 windows。

## 失败、状态与本地提醒

独立 runtime 默认优先；用户明确要诊断时才用 Computer Use，不作自动模型回退。失败码区分登录失效、身份/课程变化、页面结构变化和运行依赖等问题。保留旧任务与报告；最近失败不能刷新 `last_success`。展示旧结果时说明其时间。

`run-status.json` 记录最近尝试与成功；`notifications.json` 记录实质变化；`pending-review.json` 保存需理解或核实事项。截止提醒默认在截止前 24 小时、2 小时、30 分钟各一次，并写入本地通知状态；macOS 系统弹窗由实例配置中的 `system_notifications` 控制，没有邮件或手机推送。同步 launchd 生成器仍只生成每天本机当地时间 07:00/17:00 的配置；另用 `--mode remind` 生成每 30 分钟读取最近成功计划的提醒配置。两者都不自动启用，启用后直接运行本地 Python，不调用模型、不依赖 Codex 打开。

用户若指定 TickTick，应优先使用 `ticktick_client.py` 的核心 Open API 发布路径。Jupiter 任务 ID 与 TickTick 任务 ID 保存在私密映射文件中，重复运行只更新同一任务；一次 Jupiter 读取失败或部分课程缺失不得删除 TickTick 任务。TickTick token 只能来自实例外的环境变量或权限为 600 的本地文件。完成状态可以由 Jupiter 明确为 submitted/completed、个人 Done 或本地看板完成标记写回 TickTick；不能把 project data 中暂时缺失的任务直接当作完成。

## 用户请求诊断时的浏览器规则

只有用户要求浏览器诊断才用当前 Computer Use 工具。用户指定浏览器时遵循指定，否则优先可操作的已登录 Jupiter 标签。公开入口是 [Jupiter 登录](https://login.jupitered.com/login/)。专用采集会话与 Codex/普通 Chrome 会话分开，不复制凭据或 Cookie。选择器、索引、坐标来自当前观察；导航或展开后刷新状态。不要调用事件属性或页面内部 API，不在可分享输出中写含账户标识或认证参数的 URL。

## 事实边界

Jupiter 官方的 [学生/家长帮助](https://login.jupitered.com/help/?studlogin) 是 To Do、Calendar 与 Done 语义的参考；[集成说明](https://www.jupitered.com/integrate.php) 不等于已向学生开放作业 API。本插件不承诺学生端作业提交 API；Done 写回依赖页面中稳定可识别的个人勾选控件，找不到唯一控件时会跳过并保留旧状态。独立采集是否全程完成以本机验收记录为准，一次成功不保证未来界面、会话或课程配置保持不变。
